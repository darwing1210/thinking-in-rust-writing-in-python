Pattern 1 · Python problem

None means two things. An exception means a third.

def ingest(url: str) -> dict | None:
    try:
        raw = fetch_raw(url)
    except SourceTimeout:
        return None
    if raw is None:
        return None
    if not article["title"]:
        raise ValueError("title is required")
    return article

src/ingest/before/errors.py — missing and timeout are indistinguishable.

Pattern 1 · Rust inspiration

An expected failure is a value.

fn ingest(url: &str) -> Result { ... }
  • Ok(article) or Err(error) — not a missing object.
  • Callers handle it in the return position.
  • Rust forces that. Python will not. We can still put the failure there.
Pattern 1 · Python solution
@dataclass(frozen=True)
class Ok[T]:
    value: T

@dataclass(frozen=True)
class Err[E]:
    error: E

type Result[T, E] = Ok[T] | Err[E]
match ingest(url):
    case Ok(article):
        save(article)
    case Err(NotFound()):
        record_miss()
    case Err(ValidationFailed(f)):
        record_invalid(f)
    case Err(Retryable()):
        schedule_retry()

Pattern 1 · Trade-offs

Use it

  • More than one expected failure
  • Caller must choose: retry, skip, dead-letter
  • Boundary: HTTP, vendor, queue

Skip it

  • The failure is a bug — raise
  • House style is one exception at the edge
  • A script you will delete Friday
Pattern 2 · Python problem

A status string plus optionals can represent nonsense.

@dataclass
class Job:
    job_id: str
    url: str
    status: str = "pending"
    result: dict | None = None
    error: str | None = None

Legal: completed with no result. Failed with no error. Completed and a leftover error.

Pattern 2 · Rust inspiration

Make invalid states hard to represent.

  • One variant per state.
  • Each variant holds only the data that state needs.
  • No result: Optional hanging off the whole object.

In Python: tagged union. You already know int | str.

Pattern 2 · Python solution
@dataclass(frozen=True)
class Pending:
    job_id: str
    url: str

@dataclass(frozen=True)
class Completed:
    job_id: str
    article: Article

@dataclass(frozen=True)
class Failed:
    job_id: str
    error: IngestError

type Job = Pending | Processing
         | Completed | Failed
def finish(job: Processing, result):
    match result:
        case Ok(value):
            return Completed(
                job_id=job.job_id,
                article=value,
            )
        case Err(error):
            return Failed(
                job_id=job.job_id,
                error=error,
            )
Pattern 2 · Trade-offs

Use it

  • Jobs, orders, payments, connections
  • You must not read field X yet

Skip it

  • Optional really means optional
  • A class per JSON key in a one-off parser

Python match is not checked like Rust match. Pyright plus a small union is the honest version.

Pattern 3 · Python problem

In-place enrichment plus a shared list.

SHARED_TOPICS: list[str] = ["news"]

def enrich(article: dict) -> dict:
    topics = article.setdefault("topics", SHARED_TOPICS)
    if "bike" in body:
        topics.append("transportation")
    topics.append("ingested")
    return article

Pattern 3 · Rust inspiration

Immutable by default. Mutation you can point at.

@dataclass(frozen=True)
class Article:
    ...
    topics: tuple[str, ...] = ()

def tag_topics(article: Article) -> Article:
    topics = ["news"]
    if "bike" in article.body.lower():
        topics.append("transportation")
    return replace(article, topics=tuple(topics))
Pattern 3 · Demo and trade-offs
uv run python -m ingest pipeline --mode before
second topics include transportation

uv run python -m ingest pipeline --mode after
second topics do not

Freeze entities and pipeline values. Leave local accumulators as lists. frozen=True is a speed bump, not rustc.

Steal this

Six things, starting with one function.

  • Spot a None that means two things.
  • Put expected failures in the return type when callers choose.
  • Replace status-plus-optionals with a union of dataclasses.
  • Make mutation obvious: replace, tuples, new objects.
  • Write one SKILL.md.
  • Judge AI output on maintainability, not on “it ran.”
